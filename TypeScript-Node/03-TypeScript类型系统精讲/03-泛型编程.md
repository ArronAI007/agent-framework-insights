# 泛型编程

> 泛型这个概念你在其他语言里大概率见过（Java 的 `<T>`、C# 的 `<T>`、Rust 的 `<T>`），所以这一篇不打算从"什么是泛型"这种通用概念讲起，而是聚焦 TS 泛型里几个真正需要专门理解的地方：约束（`extends`）怎么和 `keyof` 组合出精确的字段访问类型、类里怎么用泛型、默认类型参数怎么用，以及"协变"在 TS 数组上是怎么回事。

## 学习目标

- 会写带约束的泛型函数，理解 `K extends keyof T` 这种组合的意义
- 会写泛型类，理解类的类型参数如何贯穿所有方法
- 理解泛型默认类型参数的作用
- 建立"只读视角下数组可以协变"的直觉，不深究形式化的协变/逆变定义

## 泛型约束：`K extends keyof T`

最基础的泛型函数只是把参数类型和返回类型"参数化"，比如一个 `identity<T>(x: T): T`。但真正有用的泛型往往需要给类型参数加**约束（constraint）**——限制它只能是满足某个条件的类型。TS 里最常见的约束组合是 `K extends keyof T`：

```ts
function pluck<T, K extends keyof T>(obj: T, key: K): T[K] {
	return obj[key];
}

interface Product {
	id: number;
	title: string;
	price: number;
}

const product: Product = { id: 1, title: "Mechanical Keyboard", price: 299 };
const title = pluck(product, "title"); // 推断出 title: string
const price = pluck(product, "price"); // 推断出 price: number
// pluck(product, "sku"); // 如果取消注释会编译报错："sku" 不满足约束 keyof Product
```

真实输出：

```text
title=Mechanical Keyboard (typeof string), price=299 (typeof number)
```

`keyof T` 是"取出 `T` 所有属性名组成的联合类型"（第 05 篇会专门展开 `keyof`），对 `Product` 来说就是 `"id" | "title" | "price"`。`K extends keyof T` 把类型参数 `K` 约束在这个联合类型范围内——也就是说，调用 `pluck` 时传给 `key` 参数的字符串，必须是 `T` 真实存在的属性名，传别的字符串（比如 `"sku"`）在编译期就会报错，根本不需要等到运行时才发现"这个字段不存在"。

更关键的是返回类型 `T[K]`：这是**索引访问类型（indexed access type）**，意思是"从 `T` 里取出属性 `K` 对应的类型"。因为 `K` 被约束成了 `T` 真实的属性名之一，TS 能在每次调用时**根据传入的具体 `key` 值**精确推断出返回值类型——`pluck(product, "title")` 返回类型精确到 `string`，`pluck(product, "price")` 返回类型精确到 `number`，而不是笼统的 `string | number | undefined`。这就是约束泛型的价值：既保留了函数对任意对象形状的通用性，又不牺牲每次具体调用的类型精度。

## 泛型类：`Stack<T>`

类和函数一样可以有类型参数，区别是类的类型参数会贯穿这个类的所有方法和字段——一旦实例化时确定了 `T`，这个实例上所有方法用到的 `T` 都是同一个具体类型：

```ts
class Stack<T> {
	#items: T[] = [];

	push(item: T): void {
		this.#items.push(item);
	}

	pop(): T | undefined {
		return this.#items.pop();
	}

	peek(): T | undefined {
		return this.#items.at(-1);
	}

	get size(): number {
		return this.#items.length;
	}
}

const numberStack = new Stack<number>();
numberStack.push(1);
numberStack.push(2);
numberStack.push(3);
console.log(`numberStack.pop()=${numberStack.pop()}`);
```

真实输出：

```text
numberStack.peek()=3, size=3
numberStack.pop()=3
numberStack.pop()=2
numberStack.pop()=1
empty stack pop()=undefined
```

`new Stack<number>()` 实例化时把 `T` 固定成 `number`，之后这个实例上的 `push`/`pop`/`peek` 全部按 `number` 类型检查——`numberStack.push("oops")` 会直接编译报错。注意 `pop()` 和 `peek()` 的返回类型是 `T | undefined`，不是单纯的 `T`：栈可能是空的，数组原生的 `Array.prototype.pop()`/`.at()` 在这种情况下本来就会返回 `undefined`，把返回类型如实标注成 `T | undefined` 能让 TS 强制调用方处理"栈已空"这种情况——如果调用方直接把 `numberStack.pop()` 的结果当 `number` 用（比如不做判空就 `.toFixed(2)`），TS 会因为 `undefined` 上不存在 `toFixed` 方法而报错，倒逼你在使用前先检查。这正是本课程一直强调的"用类型把隐式的运行时约定变成编译期能检查的显式约定"的又一个例子。

## 泛型默认类型参数

和函数参数可以有默认值类似，泛型类型参数也可以有默认值——调用方省略类型参数时，TS 会用默认值填充：

```ts
interface ApiResponse<T = unknown> {
	success: boolean;
	data: T;
	error?: string;
}

const rawResponse: ApiResponse = { success: true, data: { anything: "goes" } }; // T 落到默认值 unknown
const typedResponse: ApiResponse<Product> = { success: true, data: product }; // 显式传入 Product，data 的类型精确到 Product
```

真实输出：

```text
rawResponse.success=true
typedResponse.data.title=Mechanical Keyboard
```

`ApiResponse` 不写类型参数时（`ApiResponse` 而不是 `ApiResponse<Product>`），`T` 会落到默认值 `unknown`——这个选择很刻意：默认值给 `unknown` 而不是 `any`，是把第 01 篇讲的"未知类型应该强制收窄后才能用"这条原则也贯彻到泛型默认值里。如果调用方明确知道 `data` 的形状，可以显式传入 `ApiResponse<Product>`，这时候 `typedResponse.data` 的类型精确到 `Product`，能直接访问 `.title` 而不需要先做类型收窄。默认类型参数常见于这种"库/框架提供一个通用容器类型，多数场景不关心具体内容、少数场景需要精确类型"的场景。

## 协变直觉：只读视角下数组可以"安全地当作父类型使用"

TS 官方文档不会深入讲协变（covariance）/逆变（contravariance）的形式化定义，这里也不打算展开，只建立一个够用的直觉：**放弃写权限，换来"当作更宽泛类型使用"的资格**。

```ts
interface Animal {
	name: string;
}
interface Dog extends Animal {
	breed: string;
}

function announceAnimals(animals: readonly Animal[]): string {
	return animals.map((animal) => animal.name).join(", ");
}

const dogs: readonly Dog[] = [
	{ name: "Rex", breed: "Labrador" },
	{ name: "Fido", breed: "Poodle" },
];
console.log(`announceAnimals(dogs)=${announceAnimals(dogs)}`); // readonly Dog[] 被当作 readonly Animal[] 使用，编译通过
```

真实输出：

```text
announceAnimals(dogs)=Rex, Fido
```

`Dog` 是 `Animal` 的子类型（多了 `breed` 字段）。如果 `animals` 参数的类型是**可变**的 `Animal[]`，把 `Dog[]` 传进去在类型系统层面本该是危险的：函数内部一旦对 `animals` 执行 `animals.push({ name: "Cat", ... })`（一个不带 `breed` 的"猫"，甚至压根不是 `Dog`），外部拿着的 `dogs` 数组就会混入一个不满足 `Dog` 形状的元素——这正是允许可变数组协变会破坏类型安全的原因。但这个例子里 `animals` 的类型是 `readonly Animal[]`，函数内部只能读取、不能写入，不存在"往数组里塞进不兼容元素"的可能，所以把 `readonly Dog[]` 传给需要 `readonly Animal[]` 的地方是完全安全的，TS 也确实允许这样做。

这就是"数组的只读视角可以协变"这句话的具体含义：**可变数组的类型参数默认是不变的（invariant）**——`Dog[]` 不能被当作 `Animal[]` 使用（也不能反过来），因为可变性意味着"写"这个操作可能引入类型不安全；**一旦收窄到只读视角，写操作被禁止，类型参数就可以协变**——`readonly Dog[]` 可以被当作 `readonly Animal[]` 使用，因为剩下的操作（读取）不会破坏类型安全。这个直觉可以推广到别的"容器"类型：只要一个泛型容器对外只暴露读取能力，通常都能安全地"当作装着父类型的同款容器"使用。

## 小结

`K extends keyof T` 是 TS 泛型里最常用的约束组合之一，配合索引访问类型 `T[K]`，能写出"按传入的具体字段名精确推断返回类型"的通用函数。泛型类的类型参数会贯穿实例的所有方法，一旦实例化就固定下来；像 `Stack<T>.pop()` 这样如实标注 `T | undefined` 的返回类型，能强制调用方处理"容器为空"这种边界情况。泛型默认类型参数让调用方可以省略类型参数、落到一个合理的默认值（通常应该优先选 `unknown` 而不是 `any`）。协变直觉的核心是"放弃写权限换来更宽泛类型的可替换性"——只读数组可以安全地当作父类型的只读数组使用，可变数组不行。下一篇进入映射类型、条件类型和模板字面量类型，这是 TS 类型系统里"用类型计算类型"的部分，会大量用到这一篇的泛型基础。
