# 类与面向对象类型系统

> 这一篇的内容你在其他 OOP 语言里大概率都见过——访问修饰符、抽象类、接口、静态成员。所以重点不是重新讲一遍"什么是封装/继承"，而是讲 TS 在这些概念上和你熟悉的语言不一样的地方：`private` 是编译期还是运行时的限制、`implements` 和 `extends` 到底有什么本质区别、TS 特有的"参数属性简写"怎么用。

## 学习目标

- 掌握 `public`/`private`/`protected`/`readonly` 修饰符，理解它们只在编译期生效这件事
- 学会用参数属性简写省掉构造函数里的样板赋值代码
- 理解 `abstract class` 如何强制子类实现特定方法
- 分清 `implements`（接口约束）和 `extends`（继承实现）的本质区别
- 理解 `static` 成员和 getter/setter 的用法

## `abstract class`：强制子类实现特定方法

`abstract class` 不能被直接实例化，它的作用是定义一个"半成品"——一部分方法有具体实现（子类直接继承复用），一部分方法只声明签名、留给每个子类自己实现：

```ts
abstract class Shape {
	abstract area(): number;

	describe(): string {
		return `${this.constructor.name} 的面积是 ${this.area().toFixed(2)}`;
	}
}

class Circle extends Shape {
	constructor(private readonly radius: number) {
		super();
	}
	area(): number {
		return Math.PI * this.radius ** 2;
	}
}

class Rectangle extends Shape {
	constructor(
		private readonly width: number,
		private readonly height: number,
	) {
		super();
	}
	area(): number {
		return this.width * this.height;
	}
}

// const shape = new Shape(); // 如果取消注释会编译报错：无法创建抽象类的实例
const shapes: Shape[] = [new Circle(2), new Rectangle(3, 4)];
for (const shape of shapes) {
	console.log(shape.describe());
}
```

真实输出：

```text
Circle 的面积是 12.57
Rectangle 的面积是 12.00
```

`abstract area(): number` 只声明了方法签名，没有方法体——这是"抽象方法"，任何直接或间接继承 `Shape` 的非抽象类都**必须**提供 `area()` 的具体实现，否则编译期就会报错。`describe()` 则是一个普通方法，有完整实现，`Circle` 和 `Rectangle` 都不需要重写它，直接继承就能用，且内部调用的 `this.area()` 会根据实际调用者动态分派到对应子类的实现——这就是多态。`Shape` 本身因为含有未实现的抽象方法，不能被 `new` 出来，`const shape = new Shape()` 会直接编译报错，这正是抽象类存在的意义：它描述的是一个"必须被特化后才能使用"的概念，直接实例化没有意义。

## 参数属性简写：省掉构造函数里的样板赋值

TS 特有一个语法糖：在构造函数参数前加 `public`/`private`/`protected`/`readonly` 修饰符，TS 会自动帮你做两件事——声明一个同名的实例字段，并在构造函数执行时把参数赋值给这个字段，不需要你再手写 `this.x = x`：

```ts
class Point {
	constructor(
		public readonly x: number,
		public readonly y: number,
	) {}

	distanceTo(other: Point): number {
		return Math.sqrt((this.x - other.x) ** 2 + (this.y - other.y) ** 2);
	}
}

const origin = new Point(0, 0);
const target = new Point(3, 4);
console.log(`distance=${origin.distanceTo(target)}`);
```

真实输出：

```text
origin=(0, 0), target=(3, 4)
distance=5
```

不用参数属性简写的话，`Point` 得写成 `class Point { readonly x: number; readonly y: number; constructor(x: number, y: number) { this.x = x; this.y = y; } }`——同样的信息（字段名、类型、只读性）要重复写两遍。参数属性简写把"声明字段"和"构造函数参数"合并成一处声明，减少了纯样板代码，也减少了"改了参数类型忘记同步改字段类型"这类手误。这一节前面的 `Circle`/`Rectangle` 例子里 `private readonly radius: number` 用的正是同一个语法——只不过那里的修饰符是 `private`，字段不对外暴露。

## `private` 字段与 getter：对外只暴露只读访问

TS 的 `private` 修饰符只在**编译期**生效——它能阻止你在类外部写出 `instance.privateField` 这样的代码并通过类型检查，但这个字段在**运行时**依然是一个普通的对象属性，用 `JSON.stringify`、`Object.keys`，甚至简单的 `(instance as any).privateField`，都能绕过这层限制直接访问到它。如果需要运行时也真正不可访问的私有字段，要用 JS 原生的 `#` 私有字段语法：

```ts
class BankAccount {
	#balance: number;

	constructor(initialBalance: number) {
		this.#balance = initialBalance;
	}

	get balance(): number {
		return this.#balance;
	}

	deposit(amount: number): void {
		if (amount <= 0) {
			throw new Error("存款金额必须为正数");
		}
		this.#balance += amount;
	}

	withdraw(amount: number): void {
		if (amount > this.#balance) {
			throw new Error("余额不足");
		}
		this.#balance -= amount;
	}
}

const account = new BankAccount(100);
account.deposit(50);
account.withdraw(30);
console.log(`account.balance=${account.balance}`);
```

真实输出：

```text
account.balance=120
```

`#balance` 是 JS 原生私有字段语法（注意 `#` 是字段名的一部分，不是修饰符），它在运行时真正不可从类外部访问——即使写 `(account as any)["#balance"]` 也拿不到真实值，这和 TS 的 `private` 修饰符（纯编译期约束、运行时是普通属性）有本质区别。`balance` 是一个**只带 getter、不带 setter** 的访问器属性：外部代码可以读 `account.balance`，但没有对应的 setter，写 `account.balance = 999` 会直接编译报错（"balance 是只读属性"）。要修改余额，只能通过 `deposit`/`withdraw` 这些方法——这两个方法内部会做校验（金额必须为正、取款不能超过余额），保证了 `#balance` 这个内部状态任何时候都满足"合法余额"这个不变量，不会被外部代码绕过校验直接改成一个非法值。这正是封装的核心价值：**不是"藏起来不让看"，而是"只允许通过受控的入口修改，保证内部状态永远合法"**。

## `implements` vs `extends`：约束实现 vs 继承实现

这两个关键字经常被新手搞混，但语义完全不同：

- **`extends`** 是**继承**：子类继承父类已有的实现（字段和方法体），可以复用、可以重写。一个类最多只能 `extends` 一个基类——TS（和它继承的 JS 类模型）不支持多继承。
- **`implements`** 是**约束**：只声明"这个类必须提供这些方法/属性"，不提供任何实现代码，`interface` 本身也没有方法体可以继承。一个类可以同时 `implements` 多个接口。

```ts
interface Serializable {
	toJSON(): Record<string, unknown>;
}
interface Comparable<T> {
	compareTo(other: T): number;
}

class Money implements Serializable, Comparable<Money> {
	constructor(
		public readonly amount: number,
		public readonly currency: string,
	) {}

	toJSON(): Record<string, unknown> {
		return { amount: this.amount, currency: this.currency };
	}

	compareTo(other: Money): number {
		if (this.currency !== other.currency) {
			throw new Error(`无法比较不同币种：${this.currency} vs ${other.currency}`);
		}
		return this.amount - other.amount;
	}
}

const price1 = new Money(100, "CNY");
const price2 = new Money(150, "CNY");
console.log(`price1.toJSON()=${JSON.stringify(price1.toJSON())}`);
console.log(`price1.compareTo(price2)=${price1.compareTo(price2)}`);
```

真实输出：

```text
price1.toJSON()={"amount":100,"currency":"CNY"}
price1.compareTo(price2)=-50
```

`Money implements Serializable, Comparable<Money>` 声明了"这个类必须同时提供 `toJSON()` 和 `compareTo()` 两个方法"——如果 `Money` 漏写了其中任何一个，编译期就会报错，但这两个接口本身不提供任何默认实现代码，`Money` 类必须自己把方法体写全。对比前面 `Shape extends` 的例子：`describe()` 这个方法体是在 `Shape` 里写好的，子类不用重复写就能直接用——这就是 `extends` 和 `implements` 最本质的区别：**`extends` 继承的是行为（代码），`implements` 约束的只是形状（签名）**。选择用哪个，本质是在回答"子类之间是否应该共享某段具体实现代码"：需要共享实现就用 `extends`（配合 `abstract class` 描述"部分共享、部分各自实现"），只需要约束"必须支持哪些操作"、不需要共享代码就用 `implements`。

## `static` 成员：属于类本身，不属于任何实例

`static` 修饰的字段/方法属于类本身，所有实例共享同一份，不需要先创建实例就能通过类名直接访问：

```ts
class IdGenerator {
	static #counter = 0;

	static next(): number {
		IdGenerator.#counter += 1;
		return IdGenerator.#counter;
	}
}

console.log(`IdGenerator.next()=${IdGenerator.next()}`);
console.log(`IdGenerator.next()=${IdGenerator.next()}`);
console.log(`IdGenerator.next()=${IdGenerator.next()}`);
```

真实输出：

```text
IdGenerator.next()=1
IdGenerator.next()=2
IdGenerator.next()=3
```

`#counter` 加了 `static`，意味着它不属于 `IdGenerator` 的任何一个实例，而是挂在类本身上，整个程序里只有一份——三次调用 `IdGenerator.next()` 操作的都是同一个 `#counter`，所以依次返回 `1`、`2`、`3`。`static` 常用于这种"全局共享状态"（比如自增 ID 生成器）或者不依赖任何实例状态的工具方法（比如 `Money.zero(currency)` 这种"工厂方法"）。注意 `static #counter` 里 `#` 私有字段和 `static` 可以叠加使用：`#counter` 依然只能在 `IdGenerator` 类内部访问,`static` 只是决定了它挂在类上还是挂在实例上，两者是正交的两个维度。

## 小结

`public`/`private`/`protected` 是 TS 编译期的访问控制，运行时不生效，真正需要运行时私有性要用 JS 原生的 `#` 字段。参数属性简写能把构造函数参数和同名实例字段的声明合并成一处，减少样板代码。`abstract class` 定义"部分实现、部分留给子类"的半成品，不能被直接实例化，抽象方法强制每个具体子类都提供实现。`implements` 约束"必须提供哪些方法/属性"但不提供实现代码、可以多个一起用，`extends` 继承已有的具体实现、只能继承一个——这是这一篇最容易被从其他语言迁移过来的开发者搞混的一对概念。`static` 成员挂在类本身而不是实例上，所有实例共享同一份。下一篇是这一章的最后一篇，讲怎么给没有类型的第三方 JS 库手写声明文件,把这一章讲的整套类型系统真正落地到"和不完美的现实世界打交道"这件事上。
