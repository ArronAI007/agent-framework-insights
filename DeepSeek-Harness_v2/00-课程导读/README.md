# 课程导读：这套课程怎么读 DeepSeek Harness

这一篇回答三个问题：DeepSeek Harness 是什么、这套课程沿着什么主线展开、读者该按什么顺序进入。结论先说：`dsh` 是一个把"一切都做成可拔插"贯彻到底的编码 Agent 运行框架；课程围绕两条纪律（注册必须可逆、模型可见必须留痕）组织九章；已经会用的读者可以直接从第 02 章或第 03 章起读，只关心扩展的读者可以跳到第 05 章。

## 这个项目是什么

DeepSeek Harness（简称 `dsh`）是 DeepSeek 开源的编码 Agent 运行框架，和 Claude Code、Codex CLI、姊妹课程讲的 `pi` 属于同一类产品：能在终端和浏览器里跑、支持多模型和多工具、可以扩展。它区别于同类产品的地方在架构选择上，可以归成五点。

第一，运行时建立在 Cordis 这个插件框架之上，并且 Cordis 及其配套库的源码直接放进了仓库的 `vendor/` 目录，而不是作为普通 npm 依赖。框架层由项目自己拥有，可以审计，也可以打补丁。

第二，几乎每一种可替换的能力（shell、沙箱、LLM、会话存储、凭证）都按同一个三段式组织：契约、实现、消费者，课程里称作能力座（Seam）。换沙箱后端、换模型厂商，只是换一个实现包，调用方不动。

第三，Node 宿主进程（Host）和浏览器端（Client）在构建和类型上分开，靠类型安全的 RPC 和 WebSocket 通信。

第四，存在真正的跨语言边界：一个用 C 写的 Linux Landlock 沙箱启动器，和一个把整个 Node 运行时当子进程驱动的 Python SDK。

第五，工程纪律很严：`packages/*/*/src` 逐文件要求 100% 测试覆盖率，规范写进 `AGENTS.md` 由机制强制执行。仓库规模也随之而来，材料中给出的数字是约 54 个分类目录、307 个叶子包，当前版本号为 0.1.7-alpha.1。

## 主线：两条纪律

包这么多，读起来容易迷路。课程抓的主线是两条约束，插件框架、能力座、会话日志、权限旋钮都是为它们服务的。

一条是注册必须可逆：所有贡献都通过 `ctx.effect()` 或 `ctx.on()` 完成，卸载时框架自动撤销，热重载、测试隔离、会话级工具的清理都靠这一条。另一条是模型可见必须留痕：模型看到的每一段内容都必须能从会话事件日志重新构造出来，压缩只改视图、不删日志，回放和审计才成立。

后面每一章讲的具体机制，基本都能回到这两条上去。读到某个设计觉得"为什么要绕这么一圈"，多半答案就在这里。

## 章节地图

课程共九章，顺序是先能跑起来，再看地图，再拆地基，然后进入引擎、能力、边界，最后回到质量和总结。

第 01 章"快速上手"让你把 `dsh` 跑起来：安装与环境准备、`dsh web` 与 `--profile headless` 的启动、CLI 四种模式与 Profile 的叠加顺序、Provider 与模型配置、权限预设。这一章里的每个命令背后都有一个后面章节会展开的机制，读的时候留意"这里为什么是引用而不是值""为什么是两个旋钮"这类细节。

第 02 章"仓库全景与工程实践"给出工程地图：monorepo 的包结构与职责、Host 与 Client 的双面构建、分层测试与 CI 门禁、vendoring 与供应链治理。这一章不需要精读，作用是让你之后遇到任何包名都知道该往哪个目录找。

第 03 章"Cordis 插件框架基石"是和 `pi` 课程差别最大的一章：Context、Service、Plugin 三个基本概念，带类型的事件与五种派发模式，"注册即副作用、可逆卸载"的规范，以及 Profile、Bundle、Preset 怎样把插件树装配出来。不理解这一章，后面的能力座和可逆注册都读不出为什么长这样。

第 04 章"Agent 核心循环"是引擎的心脏：`ReactLoopAgent` 的 `kick`、`turn`、`step` 三层驱动，会话事件日志与 Surface，流式输出如何从 `StreamChunk` 走到界面，上下文压缩与 Checkpoint，错误处理、重试与取消。

第 05 章"能力扩展范式 CapabilitySeam"以 shell 为例讲透能力座的三元结构，随后是工具注册与执行管线、权限审批与沙箱体系、内置工具。篇幅较大，是想给 `dsh` 加新工具或新沙箱的人的主战场。

第 06 章"跨语言边界与部署形态"覆盖 `landlock-run` 原生沙箱内核、Python SDK 的 NDJSON-RPC 桥接、Host 与 Client 分离下的 Typert RPC 生成，以及对外的 ACP 协议与生态兼容 Hooks。

第 07 章"多智能体与工作流"讲 Subagent 委派与协作模型、Workflow 引擎与 Ralph 循环、Skill 技能系统与动态插件扩展。

第 08 章"工程质量与文档治理"讲测试哲学（Verify the World, not the Self-report）、`AGENTS.md` 治理规范、Postmortem 与防御性编程模式，解释前面那些强制规则为什么值得付出成本。

第 09 章"总结与延伸阅读"回顾全课程，对照同类项目，给出进一步阅读的路线。

## 谁适合读，怎么读

适合的读者大致有四类：已经在日常使用 `dsh` 或类似编码 Agent、想知道它内部怎么工作的开发者；想在 Cordis 这类插件框架上构建自己的 Agent 产品的工程师；打算为 `dsh` 写新 Provider、新工具或新 Bundle 的贡献者；学过 `pi` 课程、想对照两种取向的读者。前置要求不高：能读 TypeScript 和 Node.js 代码，了解 LLM 的基本概念（system prompt、工具调用、流式输出）即可，Cordis 从零讲起。

阅读时有三条建议。一是对照本地克隆的仓库读，课程里的文件路径都是真实路径，自己跳过去看一眼比读文字更快建立印象。二是不要试图通读仓库，每章会指出值得精读的最小文件集合。三是章节相对独立：只想学会使用的，读完第 01 章即可；想扩展的，先读第 03 章再跳到第 05 章；对上下文管理、会话日志感兴趣的，直接读第 04 章。

## 这条路的成本

课程不回避一个事实：这套重框架路线是有代价的。规模大，新人一眼看不全；不理解 Cordis 的三个基本概念，多数代码看起来只是依赖注入加事件系统；按名字查找服务让换实现很优雅，但调试时要多问一句"此刻这个服务到底指向谁"；100% 覆盖率等规则保护了系统，也抬高了贡献门槛。姊妹课程里的 `pi` 走的是精简核心加扩展点的路线，两者没有对错，只是取舍不同，课程会在相关章节标出差异。
