## 背景与目标

仓库现有六套课程（PI、DeepSeek-Harness、Hermes-Agent、OpenHarness、OpenClaw、OpenWorker）风格统一：深度剖析某个真实开源 Agent Harness 项目的源码。用户本次要求的是一套完全不同类型的内容——**面向"入门到精通"的 TypeScript / Node.js 体系化教程**，不依附于任何具体开源项目，独立成第七套课程。

用户在澄清问答中确认的方向：

1. **风格**：传统体系化教程（讲概念 + 给代码示例），而不是源码剖析驱动。
2. **受众**：已掌握其他编程语言（如 Python/Java/Go）的开发者，第一次系统学 TypeScript/Node.js。因此不讲"什么是变量/函数"这类通用编程概念，直接从 JS/TS 特有的语法、类型系统、运行时模型讲起。
3. **深度范围**：语言（TypeScript 类型系统）+ 运行时核心（Node.js 事件循环、模块、Stream、网络、进程模型）。不展开具体 Web 框架（Express/Nest 等），不做前端框架内容。
4. **形式**：Markdown 正文 + 配套可运行代码目录（`examples/`），零碎语法讲解仅写在正文里，值得"跑起来看结果"的示例才落地成 `.ts` 文件。

## 代码示例约定

- 全课程只建一个 npm 工程：`TypeScript-Node/package.json`，`devDependencies` 仅包含 `typescript`、`tsx`、`@types/node`、`vitest`。不给每章单建 `package.json`。
- `tsconfig.json` 开启 `strict` 模式，作为全课程代码示例的统一基准。
- `examples/` 目录结构镜像章节编号；正文引用代码时用相对路径标注（如 `examples/03-TypeScript类型系统精讲/03-泛型编程/generics.ts`），风格类比 PI 课程里"文中标注 `packages/agent/src/xxx.ts`，建议对照阅读"的写法。
- 不是每个行内代码块都配文件——只有"值得跑起来看结果"的示例才落地成 `.ts` 文件（如异步并发控制、Stream 处理、内存泄漏复现）；零碎语法讲解片段仍只写在 Markdown 正文的代码块里。

## 质量门槛（验收标准）

- 每个 `examples/` 下的 `.ts` 文件写完后必须跑 `tsc --noEmit` 通过类型检查；能独立执行的示例还要跑 `tsx` 确认实际输出符合正文描述。不合格视为未完成。
- 全部文章写完后做一次一致性检查：
  - 章节间术语统一（不能同一概念在不同章节用不同译名）；
  - 正文里引用的代码文件路径必须真实存在；
  - Markdown 代码块闭合（防止 fence 数量为奇数）。
- 仓库根 `README.md` 新增"课程七：TypeScript & Node.js"入口，格式与现有六套课程一致（一段简介 + 链接到 `00-课程导读` + `<details>` 展开完整目录）。

## 写作执行方式

- **脚手架先行**：先建好 `package.json`/`tsconfig.json`/`00-课程导读/README.md`，把 35 篇文章的目录骨架（含标题占位）建出来，作为后续并行写作的锚点。
- **并行分工写作**：仿照本仓库更新 PI 课程时的做法，按章节分给并行 agent 撰写，大致分组：
  - 01～02 章（环境与语法基石）
  - 03 章（类型系统精讲，篇幅最大，单独一组）
  - 04～05 章（异步模型 + Node 运行时核心）
  - 06～07 章（工程化实践 + 进阶总结）
- 每组要求：给出真实可运行、能通过 `tsc --noEmit`/`tsx` 验证的代码示例，避免空话套话和伪代码；术语准确一致。

## 明确不做的事

- 不展开具体 Web 框架（Express/Nest/Koa 等）或前端框架（React 等）的源码或用法教学。
- 第 06 章"测试体系"只是教学性讲解 Node/TS 生态里的测试工具与写法，**不是**给这门课程自身的 35 篇文章或代码示例编写单元测试套件。
- 不做源码剖析类内容（不依附任何具体开源项目）。

## 风险 / 待办

- 35 篇长文 + 配套代码是较大的工作量，写作阶段用并行 agent 分组处理，写完后仍需人工做一次全局一致性抽查。
- 类型体操（`infer`/条件类型等）章节容易写成"正确但难懂"，写作时要求每个类型体操例子配一个直观的使用场景，而不是纯理论展示。
